# 转存导入列表：上一页与单行删除

日期：2026-10-13（Asia/Shanghai）。需求见交接说明第八节第 2 项（用户 2026-10-11 确认）：转存工作区的导入列表补“上一页”，并增加单行删除；只删待转存条目，不动已转存记录。本记录只覆盖这一项。

## 行为

上一页
- “待处理链接”页签底部按钮行变为：保存修改、排除/恢复所选记录、刷新、上一页、下一页，后面显示“第 N/M 页”。
- 第一页时“上一页”不可用；往回翻回到的是原来那一页，行和序号都与之前一致；再往后翻内容也不变。
- “刷新”、保存修改、排除/恢复仍回到第一页（原有行为，未改）。
- 某一页读取失败时停在原来的页，页码不变。

单行删除
- 在待处理列表的某一行上点右键，菜单里有“删除这条记录”。右键先选中鼠标指着的那一行，所以删的一定是指着的那行；指在空白处不弹菜单。列表本来就是单选，不存在批量删除。
- 删除前弹一次确认，写明第几条、删除后不能恢复、只想这次不转存可以改用“排除所选记录”。取消则什么都不动。
- 删除是真正从本机草稿里移除（连同该行的附带内容），与“排除”不同：排除的行还留在列表里并可恢复。
- 删完留在当前页，后面的行补上来，序号保持连续；删的是最后一页的最后一行时自动退回上一页。
- 被删的若是一组重复链接里的主记录，剩下的重复行会重新归类（例如由“重复”变回“就绪”）。统计数字随之更新。
- 以下情况不能删：任务已经开始（草稿已生成转存任务，提示“任务开始后不能再删除”）；Excel 导入尚未完成、还可以“继续导入”时（否则继续导入会把删掉的行重新带回来，此时菜单项是灰的）。
- 不触碰已转存的记录、任务结果页和磁盘上的文件。

旧的独立导入页（`ImportView.xaml`）同样加了“删除所选记录”“上一页”和页码。

## 实现

- `IImportRepository.DeleteRowAsync`（默认实现抛出不支持）与 `SqliteImportRepository` 的实现：先解除其他行指向它的重复标记，删附带内容，再删该行。
- `DraftRowEditingService.DeleteAsync`：只允许可修改的草稿，核对行属于该导入，删除后走既有的重新归类与计数刷新，全程一个事务。
- `IImportWorkflow.DeleteRowAsync` 与 `LocalImportWorkflow` 的实现。
- `ImportViewModel`：记录翻过的页（游标与序号起点）以支持往回翻；新增 `LoadPreviousPageCommand`、`DeleteSelectedRowCommand`、`PageNumber`、`PageText`；翻页记录只在新页真正换上来之后才改。
- `TransferWorkspaceView.xaml` / `.xaml.cs`、`ImportView.xaml`：按钮、页码、右键菜单及“右键先选中所指行”。
- 未改助手 Python、数据库结构（无新迁移）、OTA/授权代码，未改版本号，未打包。

## 用户首次实机反馈（2026-10-13 15:00 前后）

用户导入 10,000 行表格后报告“无法点击开始转存”。用运行日志和数据库副本核对：

- 开始转存被拦的原因是这份表格里有 3 条“冲突”记录（同一链接出现多次且提取码不一致，来源行 4633、4635、7029，对应列表第 4631、4633、7027 条）。“有冲突或待处理记录时不能开始”是 2026-09-28 提交里就有的规则，与本项改动无关；导入完成时日志已有“导入内容中还有冲突或待处理记录，请先修正或排除”。
- 按钮上原本绑定了原因提示，但按钮禁用时提示不显示，用户看不到原因。已加 `ToolTipService.ShowOnDisabled`，鼠标停在灰掉的“开始转存”上会显示原因。
- 日志显示用户第一次删除成功（来源行 106），两秒后第二次删除失败。在数据库副本上用真实的服务层和导入工作流连续删除多行（含冲突行、重复组主记录）均成功，**未能重现这次失败，原因未查明**。当时的失败提示写的是“任务开始后不能再删除”，而任务并未开始，这句提示是错的。已改为按实际错误给出原因并附错误代号（如 `DRAFT_NOT_MUTABLE`、`SqliteException`），再出现时运行日志里能直接看到。新增 4 项测试覆盖这些提示。
- 修正后导入页、待处理列表、转存工作区相关 237 项测试通过。

## 用户第二次实机反馈（2026-10-13 15:10 前后）

用户找到冲突行后“删不掉”，并要求增加“只看冲突”筛选。

- 运行日志给出代号 `ROW_MISSING`：第一次删除成功，第二次删除落在一条已经不存在的记录上。上一节“未能重现”的失败就是它。
- 根因（已在真实表格 XAML 上重现并修复）：删除后新的一页里没有原来选中的那行，表格控件内部却仍记着它；之后用户再选别的行，会被它顶回去，界面模型里的“选中项”变回已删除的行。服务层和单独的界面模型都没问题，所以之前的副本重现测不出来。修复：重新载入后若原选中行已不在，先选中一条真实的行再清空，让表格放下旧行。新增 `InTheRealTableDeletingTwiceInARowActsOnTheRowChosenEachTime`，修复前失败、修复后通过。
- 新增“只看冲突”勾选框：只列出“冲突待处理”的记录，筛选时序号为冲突记录内的顺序（原表行号仍在序号提示里）；删除或排除后该行从筛选结果消失；冲突处理完（或本来没有）时自动取消筛选并提示“没有冲突记录了，已显示全部记录”；换一批导入时筛选自动关闭。筛选期间整批总数仍准确。
- 底部改为两行：上一行是链接/提取码输入框与“保存修改”“排除所选记录”，下一行左侧“只看冲突”，右侧页码、刷新、上一页、下一页。原因是用户截图里链接输入框被挤到只剩几十像素。
- 新增 4 项筛选测试；视图测试补充了筛选框存在、链接输入框宽度不小于 300、表格高度仍充足。导入页、待处理列表、转存工作区、采集结果送入转存相关 **256 项通过**；应用构建 0 警告 0 错误。
- “只看冲突”只筛“冲突待处理”一种状态；“待解析”等其他会拦住开始的状态没有单独的筛选。
