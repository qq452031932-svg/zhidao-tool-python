# 运行日志自动落盘

日期：2026-10-13（Asia/Shanghai）。用户确认暂停/续采三项实机测试“暂时没有发现太大的问题”后提出：软件自动创建一个名为“运行日志”的 TXT，把启动、采集、转存等状态自动存进去，方便出问题时排查。本记录只覆盖这一项。

## 行为

- 文件：`<数据目录>\logs\运行日志.txt`，正常安装即 `%LOCALAPPDATA%\BaiduBatchTransfer\logs\运行日志.txt`。第一次有内容要写时自动创建，之后每次启动接着往后写，不覆盖。
- 每行格式：`2026-10-13 14:21:01 [来源] 内容`，来源为 软件 / 采集 / 转存 / 分享。
- 记录内容：
  - 软件：启动及版本、启动未继续的原因（例如已在运行）、主窗口打开、关闭及退出码、启动失败和未处理异常的完整信息。
  - 采集：界面运行日志里的每一条，加上只显示在状态栏的提示（例如“采集进行中…”“请先填入 Cookie”“暂停请求未送达”）。开始时新增一行“开始采集：精准/模糊模式，关键词 N 个，目标 M 条”，界面日志里也能看到。
  - 转存、分享：界面运行日志里的每一条；错误级别的行前加【错误】。界面上点“清空日志”不影响文件。
- 脱敏：写入前经过与转存界面日志相同的处理，Cookie、BDUSS/token、网盘链接、提取码、本机路径都不进文件，可以直接把文件发给别人排查。凭据后面同一句里的内容会一并被遮住。
- 同一来源连续重复的同一句只记一次。
- 文件超过 5 MB 时改名为 `运行日志-旧.txt`（覆盖上一份旧文件）并重新开始，最多占约 10 MB。
- 日志写不进去（磁盘满、文件被独占、目录不可写）时静默跳过，不影响采集和转存；文件开着记事本时仍可继续写。
- 未处理异常只是多记一份，不接管，软件原有表现不变。

## 过程中遇到的两件事

- `CollectPauseResumeTests.FailureDuringAContinuedRunKeepsTheTaskResumable` 在一次运行中偶发失败，单独重跑 3 次均通过。原因是测试只等“采集中”清除就断言“已暂停”，而助手线程是先后设置这两个状态。已把等待条件改为两者都满足，属于测试时序修正，产品代码未因此改动。
- 启动装配测试会真实拉起主程序验证“已在运行”分支，因此在开发机上跑这组测试会往真实的运行日志里各写三行（启动、启动未继续、关闭）。只影响开发机。
