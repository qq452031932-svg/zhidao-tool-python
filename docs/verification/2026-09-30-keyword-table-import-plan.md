# 2026-09-30 关键词表格导入设计与实施计划

## 需求与根因

用户在知道采集页直接导入下载的 Excel 榜单，不应再手工转 TXT。现有文件选择框仅推荐 TXT，但允许所有文件；Python `protocol.read_keyword_file` 无条件把文件字节按 UTF-8/GB18030 解码，XLSX 被误报成文本编码问题。

用户提供三份 XLSX 样本，关键词表头分别为「热搜索词」「高消费词」「高转化词」，其余列为指数、行业等元数据。前两份各 15310 条数据，第三份 5053 条。

## 设计

- 沿用现有「从文件导入」入口及 read_keywords 协议，支持 XLSX、CSV、TSV、TXT；不调用 Office，不增加打包运行时依赖。
- XLSX 使用 Python 标准库按工作簿关系读取第一个可见非空工作表，支持共享字符串、内联字符串和稀疏单元格。表头前允许标题/空行；识别上述榜单表头及关键词/关键字/搜索词等常见列名，只导入选定列。
- 无表头的单列文件读取该列；无法确定关键词列的多列表格明确报错，不把指数/行业当关键词。旧 XLS 明确提示格式不支持，不报编码错误。
- 保留顺序、去空白、去重、追加现有关键词；沿用 8 MB 文件和 10000 条关键词上限，超限明确提示。给压缩包解压大小、XML、行扫描加边界。
- UI 文件筛选明确列出格式；读取失败保留已有关键词；更新来源提示并保护导入期间按钮状态。
- 审查补充：合并后总数同样受 10000 上限保护，现有词优先，按顺序去重。显示文件去重词数、本次实际新增数、当前总数；重复导入不在输入框重复追加。
- 导入单元格内的逗号作为词内标点保留；单元格换行归一为空格。首次导入前仍支持原有手填逗号分词；成功导入后本页面按每行一个词处理，并同步更新输入提示，保证编辑与撤销不会把词内标点变成分隔符。
- 导入忙碌状态维持至收到 keywords/error 或断连；解析失败和空表不清空原输入。
