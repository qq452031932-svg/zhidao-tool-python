# 2026-09-30：采集保守提速

用户在原版规则实测通过后反馈五个关键词、模糊目标十条耗时大半小时，选择“复用正常页面、达标立即收尾”的保守方案；没有授权更改无密码计数、搜索深度、时间优先级或缩短请求间隔。本轮未改变这些决策或 UI。

## 目标数量含义

模糊模式的目标十条是整批的全局上限，不是每关键词两条，也没有对所有候选先做全局质量排名。程序依次处理时间阶段（月、年、全部）；每个阶段按输入词顺序，逐词尝试句式和分页，累计满目标即止。因此可能第一个词六条、第二个词四条，也可能第一个词占满十条。此次优化保持该规则。

## 代码变化

- 新增助手与外层 `lxds/page_cache.py`，通过 `CachedFetcher` 适配普通和固定出口 fetcher。同任务知道搜索、详情、百度站点搜索共享有界 LRU 内存缓存，最多128页、400万字符；超大页或未知 URL不存储。
- 详情按严格知道主机和问题 ID统一 `.html`、来源参数等形式；搜索保留词和页码区别。判别基于 URL而非purpose，因为原版站点补量详情也使用search purpose。首次请求参数原样转交。
- 只缓存可识别的正常页面；普通无结果、验证、异常、删除、截短详情不缓存。正文容器成功解析的详情可缓存；整页 fallback 需有可提取分享链接。缓存命中仍走原有解析、日期、去重和统计。
- `SlotPool.on_risk` 与 `on_silent_risk` 仅新增缓存代际递增，不改变分支。缓存命中前和底层请求返回后检查，风险发生即失效旧页面；健康探针直接访问pool，不使用缓存。
- `run` 入口重置缓存，成功/停止/异常退出都在 finally清理。缓存不落盘、不存入断点、不跨任务；活网页在同任务内可能使用第一次取得的快照，新任务重新获取。
- 达到精准或模糊目标后不再发起常规搜索/随机打开回答。现有日志增加“本轮复用已获取页面 N 次”汇总，界面布局与功能入口不变。
