# M14 采集调度实施计划

依据：`PRD-拉新流水线重建-v1.md` 的 M14；设计已由该 PRD 确定。仅修改 `lxds/collect.py`、`tests/test_collect.py`、`demo/collect_demo.py` 和本文。

## 设计

`CollectWorker` 用 callback 输出进度及结果，复用 M11 解析、M13 请求池、M15 断点和 M07 补量。精准模式按关键词顺序处理，单词最多写入一条；模糊模式按最近一月、最近一年、全部三档搜索到目标数量。每页解析问题详情，以链接归一键和资源名分别去重。每 3–6 次真实搜索穿插常规问题搜索，结果不入库。连续五个空关键词或五个空页调用账号池健康探针。断点在每个查询完成以及停止时保存；恢复时跳过已完成查询。

补量只使用直连账号：在调用 `PinnedExitFetcher` 前确认直连槽存在，避免它内部的代理回退。补量风险或异常结束时保留此前结果。网络调用通过注入 fetcher 和补量工厂进行离线模拟。

## 实施步骤

1. 在 `tests/test_collect.py` 写失败测试：精准每词上限、模糊时间放宽与目标、连续五空探针、3–6 次穿插、去重和 pn 停滞。
2. 运行 `python -m pytest tests/test_collect.py -q` 确认缺少实现而失败。
3. 实现 `lxds/collect.py` 最小采集循环，通过上述测试。
4. 增加失败测试：停止小于一秒并保存断点、恢复、直连补量和风险保留；实现并复测。
5. 写 `demo/collect_demo.py`，以纯 mock 数据展示两模式，无真实请求。
6. 运行模块测试、全量测试和 demo，记录未验证项。

## PRD 尚缺数值与未验证项

- 页面正常但无网盘链接的连续关键词阈值。原打包产物可见 `SILENT_RISK_MISS=15`，但 PRD 未明确该常量是否对应这一条件；M14 当前不按该值执行重搜。
- 连续被限制时的重搜次数上限。原打包产物可见 `MAX_SILENT_RETRY=1`，但 PRD 未说明其触发范围；M14 当前由 M13 分级风控处理，异常查询不自动重搜。
- “长时间未收到处理结果”的超时秒数。

这些规则不设置臆测数值，待原实现或产品方核对后补齐。PRD 的连续五空优先于原包 `SILENT_RISK_MISS=15`。停止时的池等待和断点保存已做小于一秒的离线验证；同步 HTTP 请求在途时仍受 M13 请求超时约束，尚未验证该场景的一秒退出。真实百度端到端运行不属于离线测试结果。
